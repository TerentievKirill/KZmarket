# KZmarket — интернет-магазин электроники

Рабочий каркас интернет-магазина на **WordPress + WooCommerce**, в Docker Compose.
Оформление вдохновлено привычными интернет-магазинами электроники (вроде shop.kz),
но это самостоятельная тема, без копирования чужого дизайна и логотипов.

## Что реализовано

- Главная страница: баннер, категории, подборка товаров.
- Каталог: разделы, поиск, сортировка, фильтры по цене и атрибутам товаров.
- Карточки: фото, цена, наличие, характеристики и кнопка покупки (WooCommerce).
- Корзина и оформление заказа без обязательной регистрации.
- Заказы и остатки в панели WooCommerce.
- Роли: **Администратор** и стандартный **Shop Manager** (менеджер магазина).
  Менеджер может работать с товарами, категориями и заказами, но не устанавливает плагины и темы.
- Импорт/экспорт CSV через штатную панель «Товары».
- Адаптация под телефон, планшет и компьютер.
- Отдельная MariaDB и сохраняемый том WordPress для установки плагинов и загрузки фотографий.

**Пока не включены:** онлайн-эквайринг/Kaspi, интеграции с 1С и маркетплейсами,
товарные фотографии и реальный каталог клиента, доставка с автоматическим расчётом тарифов.
Оформление заказа работает в режиме «заявка/оплата при получении», без списания денег.
Для тестов задан способ доставки «стоимость уточняется менеджером» с нулевой
стоимостью в заказе. Это **не обещание бесплатной доставки**; до реальных продаж
владелец должен настроить условия и тарифы.
До начала продаж необходимо заполнить юридические и информационные страницы.

## Требования

- Linux VPS с Docker Engine и плагином `docker compose` (рекомендуется от 2 vCPU / 4 ГБ RAM).
- Домен и TLS-сертификат (например, через Nginx + Let's Encrypt).
- Интернет для первоначальной загрузки Docker-образов и плагина WooCommerce.

## Быстрый запуск

```bash
git clone https://github.com/TerentievKirill/KZmarket.git
cd KZmarket
cp .env.example .env
```

В `.env` обязательно укажите сложные пароли `DB_PASSWORD`, `DB_ROOT_PASSWORD`,
`WP_ADMIN_PASSWORD`, настоящий `WP_ADMIN_EMAIL`, адрес в `SITE_URL`, например
`https://shop.example.kz`. Файл `.env` не добавляется в Git.

Если используется собственный Nginx с HTTPS, оставьте `HTTP_BIND=127.0.0.1`,
`HTTP_PORT=8080` и проксируйте домен на этот порт (пример `deploy/nginx.example.conf`).

```bash
chmod +x scripts/*.sh
./scripts/install.sh
```

Скрипт поднимает базу и WordPress, создаёт администратора, активирует WooCommerce,
включает тему, задаёт валюту ₸, гостевое оформление, создаёт информационные страницы-заглушки.
Повторный запуск не создаёт второго администратора и не дублирует страницы.

Административная панель: `SITE_URL/wp-admin/`.
При первом запуске поисковая индексация отключена. Перед открытием магазина
для покупателей разрешите индексацию в **Настройки → Чтение**.

### Роль менеджера

В WordPress: **Пользователи → Добавить нового → Роль: Shop Manager / Менеджер магазина**.
Менеджер редактирует категории в **Товары → Категории**, характеристики в
**Товары → Атрибуты**, товары в **Товары**, заказы в **WooCommerce → Заказы**.
Права на плагины и системные настройки остаются у администратора.

### Тестовый каталог

Для демонстрации можно добавить семь категорий и восемь условных товаров:

```bash
./scripts/seed-demo.sh
```

Команда безопасна для повторного запуска: товары помечены SKU `DEMO-001` и т.д.
**Перед запуском реальных продаж эти демонстрационные товары нужно удалить.**
Настоящий каталог заполняет заказчик самостоятельно через админку или штатный CSV-импорт.

### Изменение темы

Файлы оформления находятся в `theme/kzmarket/`. Эти исходники смонтированы в контейнер
только для чтения, поэтому Git остаётся источником изменений темы.
Изображения и установленные через админку плагины живут в `wordpress_data`.
Логотип меняется в настройках внешнего вида WordPress. Там же администратор
может изменить телефон, надпись и изображение главного баннера.
Карточки раздела «Акции и скидки» появляются автоматически, когда у товаров
назначены скидочные цены.

## Проверка

```bash
./scripts/smoke.sh https://shop.example.kz
```

Нужно также вручную пройти сценарии:

1. Администратор создаёт пользователя с ролью Shop Manager.
2. Менеджер создаёт категорию и товар с остатком, фотографией и ценой.
3. Гость на телефоне ищет товар, добавляет в корзину и оформляет заказ.
4. Менеджер видит заказ в панели и может изменить его статус.
5. Менеджер меняет цену/остаток, покупатель видит изменение в каталоге.
6. Проверить фильтры по цене и добавленным атрибутам, оформление без авторизации.

Перед запуском настоящего магазина также настройте исходящую почту SMTP
(иначе подтверждения заказов могут не доставляться), действительные контактные
данные, политику конфиденциальности, доставку, возвраты и выдачу чеков.

## Резервные копии и переезд на другую VPS

**Образ контейнера не содержит базу заказов и фотографии.** Реальные данные лежат
в двух именованных томах: `db_data` и `wordpress_data`. Для переноса нужны Git-исходники,
файл `.env`, дамп БД и архив `wp-content`.

Создать резервную копию:

```bash
./scripts/backup.sh
```

В `backups/<дата>/` будут `database.sql` и `wp-content.tar.gz`.
Эта папка исключена из Git: там хранятся личные данные покупателей.
Храните копию **отдельно от VPS**.

Для переноса:

1. Сделайте резервную копию и остановите приём новых заказов на старом сайте.
2. На новой VPS клонируйте репозиторий, настройте `.env` и запустите контейнеры.
3. Восстановите SQL-дамп в MariaDB и содержимое `wp-content` в том WordPress.
   **Не запускайте импорт поверх действующего магазина без отдельной резервной копии.**
4. При смене домена выполните `wp search-replace` через WP-CLI (это важно для
   сериализованных данных WordPress), затем обновите `SITE_URL` и настройки HTTPS.
5. Проверьте каталог, изображения, заказы и тестовую покупку перед переключением DNS.

Не переносите базу через SQL-замену строк вручную: это может испортить сериализованные поля.

## Развитие

WooCommerce поддерживает расширения, REST API и вебхуки. Позже можно подключить
оплату Kaspi, доставку, учётную систему или маркетплейсы отдельными модулями.
